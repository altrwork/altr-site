Engineering

A property platform with no servers behind it.

mortr and the connector that feeds it run entirely on Cloudflare Workers. There is no machine to patch, no capacity to plan for, and no region to pick. The code runs in whichever Cloudflare city the request arrives in, so a broker in Tampa and one in Manhattan are served from equally close by.

It is two Workers. One serves the application and its screens on its own domain; the other is the records connector that AI clients speak to. They reach each other over a service binding rather than a public HTTP call, so an internal request never leaves Cloudflare’s network, never crosses the public internet, and costs nothing in latency.

State lives in two D1 databases: one for accounts, billing and documents, one holding the Florida corporate registry the ownership lookups run against. Sign-in links are sent by the platform itself through an email binding, so there is no mail vendor in the path either.

Scheduled work, on two different clocks.

The same Workers wake up on cron triggers and do the jobs nobody should have to remember.

The registry, weekly

Florida publishes one corporate-filing file per day. A Sunday run walks the previous eight days in one pass, with margin so a late publish is caught rather than missed. The thing it is looking for is an LLC formed to buy a building, which takes weeks to close, so a weekly cadence catches it comfortably.

Billing, nightly

A second trigger reconciles the platform’s billing state against Stripe every morning at 04:40, repairing anything a missed webhook left wrong.

Stateless on purpose.

The connector builds a fresh server for every request instead of keeping one alive per user.

One Worker, five tool sets

Because nothing is held between requests, the same Worker can expose a different set of tools on each route — valuation, sales, debt, property management, or everything. Adding a route for a new team is one entry in a table and a redeploy.

Less to go wrong

There is no long-lived object to leak, wedge, or migrate between versions. Every request starts from the same known state, which is the cheapest correctness guarantee available.
