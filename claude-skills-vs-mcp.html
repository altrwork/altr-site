Claude Skills vs MCP: a Skill teaches Claude how, an MCP server gives it a way in.

Both extend Claude, and teams mix them up constantly. One question separates them: does Claude need new instructions, or access to a system it cannot reach today?

Short answer

A Claude Skill is a folder of instructions, and optionally scripts and reference files, that Claude loads when a task matches its description. An MCP server is a running service that lets Claude read or change a system it cannot otherwise reach. Use a Skill when Claude has the access but does the task inconsistently. Use MCP when it lacks the access. Many workflows need both.

What is the difference between a Claude Skill and MCP?

A Skill is knowledge and an MCP server is access. A Skill changes how Claude works. An MCP server changes what Claude can touch.

A Skill is a folder with a SKILL.md file: a short YAML header with a name and a description, then instructions. It can also carry scripts, templates and reference documents. Claude keeps only the name and description of each installed Skill in view, and reads the full file when a request matches. There is nothing to host and no sign-in to manage.

An MCP server is a program that speaks the Model Context Protocol. It exposes tools, such as "search contacts" or "create a booking", that Claude can call against a live system, under a real identity. It has to be deployed, secured and kept running like any other service.

How do you decide which one you need?

Ask what Claude got wrong the last time it tried the task.

  • It had the information but did it differently each time. Wrong format, skipped a step, ignored your house style. That is a Skill.
  • It asked you to paste something in, or guessed. The data lives in a system Claude cannot see. That is an MCP server, or a connector a vendor already publishes.
  • It could see the system but used it badly. Called the wrong tool, used the wrong filter, forgot to check a second record. That is a Skill that teaches the procedure for the tools you already have.
  • It needs to act somewhere with a named person's permissions. That is MCP, because only a server can enforce who may do what.

Check the connector directory in Claude before building anything. If a vendor already publishes a connector for the tool, the work left is usually a Skill.

How do Skills and MCP work together?

The Skill is the playbook and the MCP server is the equipment. A good Skill names the tools it expects, the order to call them in and the checks to make between calls.

Anthropic's authoring guidance says a Skill that uses MCP tools should name them in full, as ServerName:tool_name, so Claude can find the right one when several servers are connected. A Skill that says "look up the account in the CRM" with no CRM connection does not give Claude access. It gives Claude an instruction it cannot follow.

spARK Labs uses both. A remote MCP server gives Claude access to BossHub, Verkada, Nexudus and Outlook (case study), and the rules for matching founders to advisors live in a Claude skill that proposes pairs for the team to review (case study).

Two newer packaging layers sit on top. In Claude, a plugin bundles skills, connectors and sub-agents so a team installs one thing. And Claude Cowork, which Anthropic began merging into ordinary Claude conversations in September 2026, is where multi-step tasks run, using whichever Skills and connectors are installed.

Where do teams go wrong?

  • Building a server for what is really a style guide. If Claude already has the data, a server adds hosting, secrets and uptime for no gain.
  • Hiding access inside a Skill. A script with an API key pasted into it works for one person and has no per-user permissions or audit trail. Shared business systems belong behind a server with sign-in.
  • A description that never triggers. Claude chooses a Skill from its description alone. "Helps with reports" rarely fires. See how to write a SKILL.md.
  • One giant tool. An MCP tool that "updates any record" makes the Skill's job harder, not easier. Narrow tools are easier to instruct and to secure. See MCP server design.
Working rule

If you are writing instructions, write a Skill. If you are writing code that holds credentials, you are building an MCP server. Build the Skill first and the server only when Claude still cannot reach what it needs.

Common questions

Can a Claude Skill call an API?

A Skill can bundle scripts, and Claude can run them where code execution is enabled. But a script is not a managed connection: it does not handle sign-in, per-person permissions or an audit trail. For a shared business system, put the access behind an MCP server and let the Skill describe how to use it.

Do Skills work outside Claude?

Largely, yes. Anthropic published Agent Skills as an open standard in December 2025, and tools including ChatGPT and Codex, Gemini CLI, Cursor, VS Code and GitHub Copilot now read the SKILL.md format. Instructions travel well. Scripts depend on what each tool can run, so test a Skill in every tool you plan to use it with.

Which Claude plans include Skills and custom connectors?

As of September 2026, Anthropic's help center lists Skills on Free, Pro, Max, Team and Enterprise plans with code execution turned on, and custom MCP connectors on the same plans, with Free limited to one custom connector. On Team and Enterprise, an Owner adds connectors and can provision Skills for the whole organization.

Is a Claude plugin the same as a Skill?

No. A plugin is a package that can contain several Skills together with connectors and sub-agents, so a team can install one bundle instead of setting up each piece separately. A Skill is one of the things a plugin can hold.

Which should a small team build first?

Usually a Skill. It costs an afternoon, needs no hosting and fixes the most common problem, which is Claude doing a task inconsistently. Build an MCP server when people are still copying data into the chat because Claude cannot reach the system that holds it.
