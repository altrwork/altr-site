MCP vs function calling: one is how a model asks for a tool, the other is how tools get published.

They are not rivals. Function calling is the mechanism inside a model API. MCP is a protocol for packaging tools so any AI app can find and use them. An agent is the loop that uses either. Knowing which layer you are choosing saves building the wrong thing.

Short answer

Function calling, which Anthropic calls tool use, is a model API feature: your app sends tool definitions, the model replies with a structured request to call one, and your code runs it. MCP is a protocol for publishing tools from a server so any compatible AI app can discover and call them. Most MCP clients use function calling underneath. An agent is the loop that uses either.

What is function calling?

Function calling lets a model ask your application to run a function. The model never runs anything itself.

  1. Your app sends the model a list of tools, each with a name, a description and a JSON Schema for its inputs.
  2. The model decides a tool would help and replies with a structured call: the tool's name and the arguments. In Claude's API this is a tool_use block with stop_reason: "tool_use".
  3. Your code runs the function and sends the output back, in Claude's API as a tool_result.
  4. The model reads the result and either answers or calls another tool.

The tool definitions live in your code and work only in your app. Anthropic's docs call this tool use and note it is also called function calling, and OpenAI calls it function calling. Claude's API also offers strict tool use (strict: true), which makes its tool calls match your schema exactly.

What does MCP add on top of function calling?

MCP moves the tools out of one app and into a server that any compatible app can use. A client asks the server what tools it has (tools/list), hands those definitions to its model, and when the model picks one, the client sends the call to the server (tools/call).

So inside Claude, ChatGPT or Cursor, an MCP tool reaches the model through that product's own function calling. What MCP adds is everything around it:

  • Reuse. One server works in every client that supports the protocol, instead of one integration per app.
  • Discovery. Clients learn the tools at run time, so you can change the server without redeploying the apps.
  • Sign-in. A standard OAuth flow, so each person connects as themselves.
  • More than tools. Resources to read and prompts a person can pick, where the client supports them.

The definition, the transports and the sign-in rules are covered in what is an MCP server.

Where do AI agents fit?

An agent is a model running in a loop toward a goal: call a tool, read the result, decide the next step, repeat until done or stuck. Function calling is how each step is requested. MCP is one place the tools can come from. An agent can use both in the same run.

So "agent vs MCP" is not a real choice. The real questions are how much the loop is allowed to do without a person, covered in what is an AI agent, and where its tools should be defined, which is this page.

Should you build function calls or an MCP server?

  • Plain function calling when the tools serve one application you control, the list is small and stable, and nobody needs them from Claude, ChatGPT or an editor directly.
  • An MCP server when people want the system inside the AI apps they already use, when more than one app or team needs it, or when each person must sign in as themselves.
  • Both, from one server. You do not have to choose twice. As of September 2026, Claude's API can call a remote MCP server directly through its MCP connector, a beta that supports tool calls only and needs a server reachable over HTTP. OpenAI's Responses API has an mcp tool type with an approval setting. Build the server once and call it from your own product too.

A worked example. "Check an order's status" as a function call is fifty lines inside your support app, and only that app can use it. As an MCP server it is the same logic behind a URL: support staff use it from Claude, the operations team from Claude Desktop, and your app through the API connector, each person signed in as themselves. How to design those tools well is in MCP server design for internal AI tools.

What goes wrong with tool-using AI?

  • Vague tool descriptions. The model picks tools from their names and descriptions. Two tools that sound alike get confused, whichever layer defines them.
  • Missing arguments filled by guessing. Anthropic's docs note a model may infer a plausible value for a required field the user never gave. Validate inputs and ask when a required value is missing.
  • Trusting a tool's own labels. MCP lets a server mark a tool read-only, but the spec tells clients to treat those labels as untrusted. The permission check belongs in the code that runs the tool.
  • Unbounded loops. An agent retrying a failing tool burns tokens. Set step limits and timeouts.
Working rule

Function calling is how a tool gets called. MCP decides where the tool lives and who can reach it. If more than one app or person needs the tool, put it behind an MCP server.

Common questions

Is MCP replacing function calling?

No. MCP sits on top of it. An MCP client fetches tool definitions from a server and passes them to its model, which asks for a tool through the model API's ordinary function calling. MCP standardizes where tools come from and how they are called, not how the model chooses them.

Is tool use the same as function calling?

Yes. Anthropic calls the feature tool use and OpenAI calls it function calling. In both, the application describes tools with names, descriptions and JSON Schema inputs, the model returns a structured request, and the application runs the tool and returns the result.

Can my own app use an MCP server through the API?

Yes. As of September 2026, Claude's API has an MCP connector, in beta, that calls a remote MCP server's tools from a normal Messages request, and OpenAI's Responses API accepts remote MCP servers as a tool type. Both need the server reachable over HTTP. You can also build your own MCP client with the official SDKs.

Do I need an agent framework to use MCP?

No. Claude, ChatGPT, Cursor, VS Code and many other apps are already MCP clients, and the model APIs can call MCP servers directly. A framework helps when you are building your own multi-step agent, but it is not required to publish or use an MCP server.

Is an MCP server more secure than function calling?

Neither is secure by itself. Both run whatever code sits behind the tool. MCP gives you a standard OAuth sign-in and one place to enforce permissions and log calls, which helps. The limits that matter are still the ones written into the tool's own code.
